                             │
                    ┌────────┴────────┐
                    │   Nginx 反向代理  │

                    └────────┬────────┘

                    ┌────────┴────────┐
                    │  Midway.js API  │
                    │  (RESTful API)  │

                             │
              ┌──────────────┼──────────────┐
              │              │              │
       ┌──────┴──────┐ ┌────┴────┐ ┌──────┴──────┐
       │   MySQL 8.0 │ │  Redis  │ │   檔案存儲   │
       │   (主庫)    │ │ (緩存)  │ │  (圖片/影片) │
       └─────────────┘ └─────────┘ └─────────────┘

### 分層架構說明

| 層級 | 技術 | 職責 |
|------|------|------|
| **展示層** | Vue3 + Element Plus / Vant | 三端 UI 渲染、路由控制、狀態管理 |
| **閘道層** | Nginx | 反向代理、SSL 終止、靜態資源服務、API 路由轉發 |
| **業務層** | Midway.js | RESTful API 提供、JWT 鑒權、業務邏輯處理 |
| **數據層** | MySQL + Redis | 持久化存儲、緩存加速、分布式鎖 |

## 5. 緩存架構設計

### 5.1 Redis 使用場景

| 場景 | Key 命名規則 | 說明 |
|------|-------------|------|
| **JWT Token 黑名單** | `blacklist:token:{jti}` | 登出後 Token 失效 |
| **登錄會話** | `session:{shop_code}:{staff_id}` | 登錄狀態、權限快照 |
| **場務表鎖** | `lock:schedule:{staff_id}:{date}:{time}` | 分布式鎖，防止一格多約 |
| **門店配置緩存** | `config:shop:{shop_id}` | 門店營業時間、抽成規則等 |
| **服務項目緩存** | `cache:services:{shop_id}` | 服務項目列表 |
| **會員信息緩存** | `cache:member:{member_id}` | 會員基本信息 |
| **業績排行榜** | `rank:performance:{shop_id}:{date}` | 店內業績排行 |
| **驗證碼** | `captcha:{phone}` | 手機驗證碼（5分鐘過期） |
| **接口限流** | `ratelimit:{ip}:{api}` | API 調用頻率限制 |

### 5.2 緩存策略

```
┌─────────────────────────────────────────────────────┐
│                  緩存策略                            │
├─────────────────────────────────────────────────────┤
│  1.  Cache-Aside 模式                               │
│     讀：先查 Redis → 未命中查 MySQL → 回寫 Redis   │
│     寫：先更新 MySQL → 刪除 Redis 緩存              │
├─────────────────────────────────────────────────────┤
│  2.  分布式鎖 (Redlock)                             │
│     場務表預約時：SET lock:schedule NX EX 3         │
│     防止同一時段被多名美容師或客戶搶佔              │
├─────────────────────────────────────────────────────┤
│  3.  過期策略                                       │
│     熱點數據（服務項目、門店配置）：TTL 1小時       │
│     會話數據：TTL 7天                               │
│     臨時數據（驗證碼）：TTL 5分鐘                   │
└─────────────────────────────────────────────────────┘
```

## 6. API 交互規則

### 6.1 通用規範

```
基礎 URL: https://api.example.com/api/v1
請求格式: application/json
響應格式: application/json
字符編碼: UTF-8
```

### 6.2 請求頭規範

| Header | 必填 | 說明 |
|--------|------|------|
| `Authorization` | 是（登錄後） | `Bearer {jwt_token}` |
| `X-Shop-Code` | 是 | 客戶代碼（門店標識） |
| `X-Device-Type` | 是 | `pc` / `tablet` / `mobile` |
| `Content-Type` | 是 | `application/json` |
| `Accept-Language` | 否 | `zh-TW`（默認） |

### 6.3 響應體結構

```json
// 成功響應
{
  "code": 0,
  "message": "success",
  "data": { ... },
  "timestamp": 1714800000000
}

// 分頁響應
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [ ... ],
    "pagination": {
      "page": 1,
      "pageSize": 20,
      "total": 100,
      "totalPages": 5
    }
  },
  "timestamp": 1714800000000
}

// 錯誤響應
{
  "code": 40001,
  "message": "帳號或密碼錯誤",
  "data": null,
  "timestamp": 1714800000000
}
```

### 6.4 錯誤碼定義

| 錯誤碼 | 說明 |
|--------|------|
| 0 | 成功 |
| 40000 | 請求參數錯誤 |
| 40001 | 帳號或密碼錯誤 |
| 40002 | Token 已過期 |
| 40003 | Token 無效 |
| 40004 | 無操作權限 |
| 40005 | 資源不存在 |
| 40006 | 資源衝突（如時間已被預約） |
| 40007 | 請求頻率過高 |
| 50000 | 服務器內部錯誤 |
| 50001 | 數據庫操作失敗 |
| 50002 | Redis 操作失敗 |

### 6.5 登錄流程

```
客戶端                         服務器
  │                              │
  │  POST /api/v1/auth/login     │
  │  {                          │
  │    shopCode: "ABC123",      │  ← 客戶代碼
  │    username: "beautician01",│  ← 帳號
  │    password: "***"          │  ← 密碼
  │  }                          │
  │ ──────────────────────────> │
  │                              │ 驗證客戶代碼是否存在
  │                              │ 驗證帳號密碼
  │                              │ 生成 JWT Token
  │                              │ 返回用戶信息 + Token
  │  <────────────────────────── │
  │  {                          │
  │    code: 0,                 │
  │    data: {                  │
  │      token: "eyJ...",       │
  │      refreshToken: "...",   │
  │      expiresIn: 86400,      │
  │      user: {                │
  │        id: 1,               │
  │        name: "LULU",        │
  │        role: "beautician",  │
  │        shopId: 1,           │
  │        avatar: "..."        │
  │      }                      │
  │    }                        │
  │  }                          │
```

### 6.6 JWT Token 規範

```json
{
  "alg": "RS256",
  "typ": "JWT"
}
{
  "sub": "staff_id",
  "shop_id": "shop_id",
  "role": "beautician|manager",
  "iat": 1714800000,
  "exp": 1714886400,
  "jti": "unique-token-id"
}
```

- Access Token 有效期：24 小時
- Refresh Token 有效期：7 天
- Token 刷新：`POST /api/v1/auth/refresh`

## 7. 權限體系設計

### 7.1 角色定義

| 角色 | 標識 | 說明 |
|------|------|------|
| **店長/管理員** | `manager` | 擁有門店全部管理權限 |
| **美容師** | `beautician` | 僅限個人業務操作 |

### 7.2 權限矩陣

| 功能模組 | 店長 | 美容師 |
|---------|:----:|:------:|
| 場務表查看 | 全店 | 個人 |
| 場務表編輯 | 全部 | 個人 |
| 預約管理 | 全部 | 個人 |
| 會員 CRM | 全部 | 個人客戶 |
| 業績看板 | 全店數據 | 個人數據 |
| 佣金明細 | 全店 | 個人 |
| 薪資預估 | 全店 | 個人 |
| 作品集管理 | - | 個人 |
| 庫存管理 | 全部 | 僅領料 |
| 領料申請 | 審批 | 申請 |
| 員工管理 | 全部 | - |
| 服務項目管理 | 全部 | - |
| 門店設置 | 全部 | - |
| 儀表板 | 全店 | 個人摘要 |

### 7.3 權限校驗流程

```
請求到達
    │
    ▼
JWT Middleware ──── 驗證 Token 有效性
    │
    ▼
Role Guard ──── 檢查角色是否允許訪問該路由
    │
    ▼
Data Scope ──── 店長可查看全店數據
                美容師僅限 staff_id = 自己的數據
    │
    ▼
Controller ──── 執行業務邏輯
```

### 7.4 後端 Middleware 鏈

```typescript
// 中間件執行順序
[
  JwtAuthMiddleware,      // 1. JWT 驗證
  ShopCodeMiddleware,     // 2. 客戶代碼校驗
  RoleGuardMiddleware,    // 3. 角色權限校驗
  DataScopeMiddleware,    // 4. 數據範圍過濾
  RateLimitMiddleware,    // 5. 接口限流
  RequestLogMiddleware,   // 6. 請求日誌
]
```
